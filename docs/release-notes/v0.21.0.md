# Release Notes: v0.21.0

**Date:** 2026-05-28
**Tag:** `v0.21.0`

---

## Overview

v0.21.0 is the culmination of an 8-phase hardening effort that makes the Atlas daemon a
reliable daily-driver. The release unifies the submit path, hardens the runner/recovery loop,
aligns status/UI/log vocabulary, and ships architectural decision records and migration docs.

---

## What Changed by Phase

### Phase 1 — Clean Baseline + Architecture Decision Records

- Established a clean branch baseline from `origin/master` (commit `f1de323`).
- Added `docs/architecture/daemon-redis.md`: maps source-of-truth boundaries, Redis key schema,
  heartbeat/state flows, and every pre-existing audit finding.
- Added `docs/architecture/lifecycle-service.md`: documents the task-engine state machine,
  lifecycle-service contract, hook sequencing, and cancel/rollback paths.

### Phase 2 — Golden-Path Characterization Tests

- Introduced `internal/testfakes` harness providing in-process fakes for Redis (via miniredis),
  the AI runner, and the hook signer.
- Added golden-path characterization tests covering the full submit → queue → dequeue → complete
  cycle under both direct and daemon modes.
- Established a regression baseline; all existing tests continue to pass with the race detector
  enabled.

### Phase 3 — Daemon Readiness + Diagnostics

- Hardened the daemon readiness contract: the socket is now only advertised after the Redis
  connection and heartbeat goroutine are confirmed live.
- Stale socket detection: if a previous socket file exists but the daemon is not responding, Atlas
  removes the stale file and starts cleanly.
- Redis-down UX: `atlas start` now surfaces a clear human-readable error when the daemon cannot
  reach Redis, instead of a raw dial error.
- Added `atlas daemon doctor`: prints a structured health report covering socket reachability,
  heartbeat age, queue depth, and Redis connectivity.

### Phase 4 — Submit Transaction + Queue Contract

- **Direct-first default:** `atlas start` now runs in foreground/DIRECT mode by default. Pass
  `--daemon` to route work through the background daemon queue. Set `daemon.default: true` in
  `~/.atlas/config.yaml` to make daemon the permanent default.
- Transactional submit: the queue push and workspace-state write are now atomic via a Redis
  pipeline; a crash between the two no longer leaves orphaned queue entries.
- `MaxSize` queue cap: the daemon rejects new submits when the queue is at capacity and returns a
  structured error to the CLI.
- Nanosecond timestamps: queue entries carry nanosecond-resolution enqueue timestamps for
  accurate ordering and latency metrics.
- Workspace name included in submit response so callers do not need a second round-trip.
- Redis key prefix expanded to cover `heartbeat` and `daemon-state` keys, preventing cross-process
  key collisions in multi-tenant Redis instances.

### Phase 5 — Runner/Recovery Hardening

- Worktree-keyed exclusivity locks: only one runner goroutine may process a given workspace at a
  time; concurrent dequeues for the same workspace are serialised.
- Crash-window recovery: on daemon startup, any workspace that was `IN_PROGRESS` with no
  heartbeat within the liveness window is automatically re-queued.
- Hook degraded state: if a hook signer returns a permanent error, the runner marks the workspace
  `DEGRADED` rather than retrying indefinitely and burning queue slots.
- Configurable retry limits with exponential back-off; the retry counter is persisted in Redis so
  restarts do not reset the count.
- Race detector clean: all new concurrency paths verified under `go test -race`.

### Phase 6 — Status/UI/Log Truth Unification

- Unified status vocabulary: `PENDING`, `IN_PROGRESS`, `DONE`, `FAILED`, `DEGRADED` are now the
  canonical states across the CLI, TUI dashboard, and structured logs.
- Reconcile report: `atlas daemon status` now emits a reconcile summary showing queue depth, active
  runners, and any workspaces whose Redis state disagrees with the in-memory runner map.
- Degraded UI banner: the TUI dashboard displays a persistent banner when any workspace is in
  `DEGRADED` state, prompting the operator to run `atlas hook retry <workspace>`.
- JSON output mode: `atlas daemon status --json` and `atlas daemon doctor --json` emit
  machine-readable output suitable for monitoring pipelines.

### Phase 7 — Dogfood on Atlas Itself

- Added fake-AI runner integration test that exercises the full Atlas-on-Atlas submit path,
  including hook signing, queue transit, and workspace state transitions.
- Verified a clean end-to-end run on the Atlas repository itself.

### Phase 8 — Docs, Skill, Validation, Release

- Updated `docs/quick-start.md` for the direct-first default and daemon opt-in flags.
- Updated `README.md` with direct-first default and daemon opt-in notes.
- Atlas skill updated to reflect `atlas daemon doctor` and `atlas hook retry` commands.
- Phase gate validation (8.5) verified all acceptance criteria across Phases 1–8.
- This release notes file (8.6).

## Migration Notes

| Before (≤ v0.20.x) | After (v0.21.0) |
|---|---|
| `atlas start` auto-detected daemon and used it when running | `atlas start` runs **DIRECT** (foreground) by default |
| No explicit flag needed to use daemon | Pass `--daemon` to `atlas start` to use the background queue |
| No per-user config option | Set `daemon.default: true` in `~/.atlas/config.yaml` to restore the old behaviour |
| `atlas daemon` had no health subcommand | `atlas daemon doctor` is now available |
| Hook failures caused silent retries | Permanent hook errors set `DEGRADED` state; use `atlas hook retry <workspace>` to recover |
| Heartbeat and daemon-state Redis keys were unprefixed | All Redis keys now share the configured key prefix |

---

## Upgrade Steps

1. Pull the new binary: `atlas upgrade` (or replace the binary manually).
2. If you relied on daemon-by-default behaviour, add `daemon.default: true` to
   `~/.atlas/config.yaml`.
3. Run `atlas daemon doctor` to verify your daemon and Redis are healthy.
4. If any workspace shows `DEGRADED`, run `atlas hook retry <workspace>` to re-enter the queue.

---

## Compatibility

- Go 1.22+
- Redis 6.2+ (streams not required; keyspace operations only)
- No database migrations required
- Config file format unchanged; `daemon.default` is a new optional key (default: `false`)
