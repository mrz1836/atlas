Friction Observed (→ Task 7.3)
-------------------------------

FRICTION-1 [BUG — FIXED]: --daemon flag collision between global and subcommand
  Symptom:  `atlas start --daemon` silently ran the daemon process (RunDaemonProcess)
            instead of submitting to an existing daemon. This is because Execute() in
            root.go scanned ALL os.Args for "--daemon" before Cobra parsed subcommands.
  Root cause: `for _, arg := range os.Args[1:] { if arg == "--daemon" { ... } }`
              intercepts --daemon regardless of which subcommand it belongs to.
  Fix applied: Changed to only intercept when os.Args[1] == "--daemon" (i.e. atlas --daemon
               not atlas start --daemon). Committed in this phase.
  Status: FIXED in root.go, confirmed exit 1 + correct error message.

FRICTION-2 [ENV]: Redis not available on this development machine
  Symptom:  `atlas daemon start` fails; no real daemon submit possible.
  Cause:    redis-server not installed (no brew install redis / no Docker Redis).
  Impact:   Task 7.2 could not run a real daemon-mode task end-to-end.
  Mitigation: Fake dogfood (Task 7.1) proves full queue+execute+status flow with
              miniredis. Real daemon session is blocked by environment, not code.
  Recommended remediation: `brew install redis && brew services start redis` then
                           `atlas daemon start` to re-run this dogfood fully.

FRICTION-3 [OBSERVATION]: No ~/.atlas/config.yaml present
  Symptom:  atlas uses default config (localhost:6379, no custom prefix).
  Impact:   config.Load returns defaults; daemon auto-starts pointing to localhost:6379.
  Mitigation: Not a code issue; document `atlas init` / config setup as Phase 8 docs.
